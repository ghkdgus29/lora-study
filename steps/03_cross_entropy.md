# 3단계: 분류의 loss - logits · softmax · cross-entropy · 라벨 가중치

**목표**: 답 토큰 loss 함수(`answer_loss()`, 6단계) 안에 있는 `F.cross_entropy`, `weight`, `(ce * weight).sum() / weight.sum()`이 무엇인지 안다.
LLM의 "다음 토큰 예측"은 어휘(Qwen3.6은 248,320개) 중 하나를 고르는 **분류 문제**이므로, 클래스 3개짜리로 보면 전부 보인다.

## 핵심 개념

### logits → softmax → 확률
- **logits**: 모델이 클래스마다 낸 점수. 아무 실수나 될 수 있다(음수도).
- **softmax**: `exp(점수) / exp(점수)의 합`. 점수를 "합이 1인 확률"로 바꾼다. 점수 차이가 크면 확률이 한쪽으로 쏠린다.
- LLM은 위치마다 어휘 전체에 대한 logits를 낸다 → shape `[배치, 길이, 어휘 수]`. 실전 코드가 `logits_to_keep`를 쓰는 이유가 여기서 나온다(6단계).

### cross-entropy = -log P(정답)
**무엇을 재나.** 1·2단계의 loss는 `(pred − y)²`, 즉 "예측 숫자가 정답 숫자에서 얼마나 떨어졌나"였다.
분류에서는 모델 출력이 숫자 하나가 아니라 **클래스마다 확률 하나씩**(합 1)이고, 정답은 "몇 번 클래스냐"다.
그래서 "떨어진 거리" 대신 **정답 클래스에 준 확률이 얼마나 1에 가깝나**를 잰다. 다른 클래스에 준 확률은 직접 보지 않는다
(합이 1이므로 정답에 0.8을 줬으면 나머지는 자동으로 0.2다).

예: 클래스 3개, 모델이 `[0.7856, 0.1753, 0.0391]`을 냈다.
- 정답이 0번이면 P(정답) = 0.7856 → loss = −log 0.7856 = 0.24
- 정답이 2번이면 P(정답) = 0.0391 → loss = −log 0.0391 = 3.24

같은 출력인데 정답이 무엇이냐에 따라 loss가 다르다. 보는 칸이 다르기 때문.

**왜 −log인가.** 확률 p를 그대로 쓰면 "클수록 좋다"인데 loss는 "작을수록 좋다"여야 하고, 0~1 사이 값이라 차이가 밋밋하다.
−log p는 다음 성질을 준다.

| P(정답) | −log P | 뜻 |
|---|---|---|
| 1 | 0 | 완벽. 벌점 없음 |
| 0.9 | 0.105 | 거의 맞음 |
| 0.5 | 0.69 | 반반 |
| 0.1 | 2.30 | 많이 틀림 |
| 0.04 | 3.22 | 확신하며 틀림 |
| 0.001 | 6.9 | 정답에 거의 0을 줌 → 벌점이 끝없이 커진다 |

0.9 → 0.99로 올려도 loss는 0.105 → 0.01, 즉 0.1 정도만 준다. 반면 0.04 → 0.001로 틀린 확신이 커지면 3.2 → 6.9로 3.7이나 뛴다.
그래서 학습은 "이미 맞는 것을 더 확실하게"보다 **"확신하며 틀리는 것을 고치는" 쪽에 훨씬 큰 기울기**를 준다(기울기는 다음 절).

**코드.** `F.cross_entropy(logits, target)`는 점수(logits)를 받아 softmax → 정답 칸 고르기 → −log 를 한 번에 한다.
수식으로는 두 단계를 합쳐 놓은 것이다. 정답을 t번이라 하면

```
P(t) = exp(z_t) / Σ_j exp(z_j)
loss = −log P(t) = log( Σ_j exp(z_j) ) − z_t          ← log(a/b) = log a − log b, log(exp(z)) = z
```

즉 "모든 점수의 exp를 더해 log를 취한 값"에서 "정답 점수"를 뺀다. 이 식을 쓰면 확률 P(t)를 숫자로 만들 필요가 없다.

왜 따로 하면 안 되나. 컴퓨터의 float32는 약 3.4×10³⁸까지만 담는다. `exp(89)`부터 넘쳐서 `inf`가 되고, `exp(−104)` 아래는 0이 된다.
- 점수가 `[1000, 999, 998]`이면 `exp` 셋 다 `inf`, softmax는 `inf/inf = nan`, loss도 `nan`. 그런데 진짜 답은 0.41이다(점수 차이가 1, 2뿐이므로).
- 점수가 `[0, 110]`이고 정답이 0번이면 P(0) = 1/(1 + e¹¹⁰)은 float32에서 0이 되고, `−log 0 = inf`. 진짜 답은 110이다.

log-sum-exp 트릭: 점수 전부에서 **최댓값 m을 빼고** 계산해도 softmax는 같다(분자·분모에 같은 e^m이 곱해져 있으므로 약분된다).
```
loss = log( Σ_j exp(z_j − m) ) + m − z_t
```
빼고 나면 가장 큰 점수가 0이 되어 `exp`가 절대 넘치지 않고, 합은 최소 1(= exp(0))이라 `log`에 0이 들어갈 일도 없다.
- `[1000, 999, 998]` → m = 1000, 빼면 `[0, −1, −2]`, exp = `[1, 0.368, 0.135]`, 합 1.503, log = 0.408 → loss = 0.408 + 1000 − 1000 = **0.41**
- `[0, 110]` → m = 110, 빼면 `[−110, 0]`, exp = `[0, 1]`, 합 1, log = 0 → loss = 0 + 110 − 0 = **110**

`F.cross_entropy`가 안에서 이 식을 쓴다. LLM은 logits가 수십 단위로 흔히 나오고 어휘가 248,320개라 합이 금방 커지므로 꼭 필요하다.
`torch.log_softmax`도 같은 트릭이다. 손으로 할 때는 점수가 작으니 softmax를 따로 구해도 값이 같다(스크립트 A가 두 방식을 비교한다).

**학습 로그의 loss와의 관계.** 위에서는 "예시 하나 = 클래스 3개 중 정답 하나"였다. LLM에서는 이것이 **답 토큰 하나**에 해당한다.
- 클래스 = 어휘 248,320개. 모델은 위치마다 "다음 토큰은 뭐냐"에 대해 어휘 전체에 점수를 낸다(= logits 248,320개 → softmax → 확률 248,320개).
- 정답 = 그 위치에 실제로 와야 하는 토큰 id.
- 그러니 답이 토큰 5개면 분류 문제가 5개 있는 것이고, 각 위치에서 "정답 토큰에 준 확률"을 하나씩 얻는다.

예: 답이 `[1] Y\n` 이고 토큰이 `[`, `1`, `]`, ` Y`, `\n` 다섯 개라 하자. 모델이 각 위치에서 정답 토큰에 준 확률이 아래와 같았다면

| 위치 | 앞에 보인 것 | 정답 토큰 | P(정답 토큰) | −log P |
|---|---|---|---|---|
| 1 | 프롬프트 | `[` | 0.95 | 0.051 |
| 2 | 프롬프트 + `[` | `1` | 0.90 | 0.105 |
| 3 | … + `[1` | `]` | 0.99 | 0.010 |
| 4 | … + `[1]` | ` Y` | 0.60 | 0.511 |
| 5 | … + `[1] Y` | `\n` | 0.98 | 0.020 |

로그에 찍히는 `loss` = 다섯 값의 평균 = 0.698 / 5 = **0.14**. 가중치를 쓰면(` Y`에 3) `(0.051 + 0.105 + 0.010 + 3·0.511 + 0.020) / (1+1+1+3+1)` = 0.246 로, ` Y`를 못 맞힌 것이 더 크게 반영된다.
실전은 답이 52토큰이라 행이 52개일 뿐 똑같다.

**loss 숫자를 확률로 읽기.** 평균 loss가 L이면 토큰마다 −log P ≈ L, 뒤집으면 P ≈ e^(−L)이다.

| 로그의 loss | e^(−loss) | 뜻 |
|---|---|---|
| 0.1 | 0.90 | 답 토큰마다 정답에 약 90% |
| 0.69 | 0.50 | 반반 |
| 2.3 | 0.10 | 정답에 10%만 |

왜 이렇게 읽을 수 있나. 먼저 로그 법칙 복습. log는 "e를 몇 제곱하면 이 수가 되나"이고, 지수 법칙 `e^a · e^b = e^(a+b)`, `(e^a)^k = e^(ak)` 를 그대로 뒤집은 것이다.

| 지수 법칙 | 로그 법칙 | 숫자 예 |
|---|---|---|
| e^a · e^b = e^(a+b) | log(x·y) = log x + log y | log(2·4) = log 8 = 2.079 = 0.693 + 1.386 |
| (e^a)^k = e^(ak) | log(x^k) = k·log x | log(2³) = log 8 = 2.079 = 3 × 0.693 |
| 위의 k = −1 | log(1/x) = −log x | log(1/2) = −0.693 |

이걸로 loss를 고쳐 쓰면
```
loss = (−log P₁ − log P₂ − … − log P₅) / 5
     = −(log P₁ + log P₂ + … + log P₅) / 5      ← 마이너스 묶기
     = −log(P₁ · P₂ · … · P₅) / 5               ← log 합 = 곱의 log  (첫째 법칙)
     = −log( (P₁ · P₂ · … · P₅)^(1/5) )          ← (1/5)·log x = log x^(1/5)  (둘째 법칙, k = 1/5)
```
`x^(1/5)`는 5제곱근이다.
괄호 안은 다섯 확률을 **곱해서 5제곱근** 한 것(기하평균)이므로, loss = −log(기하평균), 뒤집으면 기하평균 = e^(−loss) 다.
위 예: `0.95 × 0.90 × 0.99 × 0.60 × 0.98 = 0.498`, `0.498^(1/5) = 0.87`, 그리고 e^(−0.14) = 0.87 로 맞는다.
흔히 말하는 "평균 확률"(더해서 5로 나눈 산술평균 0.88)과는 다르지만 값이 비슷하므로, 로그의 loss를 보고 "토큰당 정답 확률이 대략 e^(−loss)"로 읽으면 된다.

**주의: 평균이 숨기는 것.** 위 표에서 `[`, `]`, `\n` 같은 형식 토큰은 "항상 그 자리에 그 글자가 온다"라 모델이 금방 0.95~0.99를 준다. 이것들의 −log는 0에 가까워 평균을 작게 만든다.
위 예의 loss 0.14를 e^(−0.14) = 0.87로 읽으면 "토큰당 87% 맞힌다"지만, 정작 중요한 ` Y` 자리는 0.60 이다. 즉 **5개 중 4개가 쉬운 토큰이라 평균이 좋아 보이는 것**이지 Y/N을 잘 고르는 게 아니다.
실전은 52토큰 중 42개가 형식 토큰이라 이 효과가 더 크다. 그래서 loss 평균만으로 "Y/N을 잘 고른다"고 말할 수 없고, 6단계에서 토큰별 loss를, 8단계에서 F1을 따로 본다.

### 기울기 = softmax - one-hot
cross-entropy를 logits로 미분하면 정확히 `확률 - 정답 one-hot`이다. 정답 클래스만 음수(점수를 올려라), 나머지는 양수(내려라).
학습이 하는 일은 결국 "정답 토큰의 점수를 올리고 나머지를 내린다"의 반복이다.

**유도.** 위에서 정리한 식 `loss = log( Σ_j exp(z_j) ) − z_t` 를 점수 z_i 하나로 미분한다. 두 항을 따로 본다.

① 첫 항 `log(S)`, S = Σ_j exp(z_j).

먼저 쓸 미분 공식 세 개.
```
d log(x) / dx = 1 / x
d exp(x) / dx = exp(x)                       ← exp는 미분해도 자기 자신
d f(g(x)) / dx = f'(g(x)) · g'(x)            ← 합성함수(연쇄 법칙): 바깥 미분 × 안쪽 미분
```
연쇄 법칙은 1단계에서 쓴 것과 같다. "x가 조금 변하면 g가 g′만큼 변하고, g가 조금 변하면 f가 f′만큼 변하니, 합쳐서 f′·g′".

`log(S)`는 바깥이 log, 안쪽이 S인 합성함수다. z_i로 미분하면
```
d log(S) / dz_i = (바깥 미분) × (안쪽 미분)
               = (1 / S)   ×  dS/dz_i
```
안쪽 미분 `dS/dz_i`: S = exp(z₁) + exp(z₂) + … + exp(z_n) 인데, z_i로 미분하면 z_i가 없는 항은 상수라 0이 되고 `exp(z_i)` 항만 남는다. 그 항의 미분은 exp(z_i) 자기 자신.
```
dS/dz_i = 0 + … + exp(z_i) + … + 0 = exp(z_i)
```
합치면
```
d log(S) / dz_i = (1 / S) · exp(z_i) = exp(z_i) / Σ_j exp(z_j) = p_i        ← softmax 확률 바로 그것
```
클래스 3개, i = 1로 써 보면: S = e^z₁ + e^z₂ + e^z₃, `dS/dz₁ = e^z₁`, `d log(S)/dz₁ = e^z₁ / (e^z₁ + e^z₂ + e^z₃) = p₁`.
② 둘째 항 `−z_t`. t는 정답 번호 하나로 고정된 값이다. 클래스 3개, 정답이 3번(t = 3)이면 둘째 항은 그냥 `−z₃` 다.
- z₁로 미분: `−z₃` 안에 z₁이 없다 → 상수 취급 → 0
- z₂로 미분: 마찬가지로 0
- z₃로 미분: `d(−z₃)/dz₃ = −1`

셋을 나란히 쓰면 `[0, 0, −1]`. 정답 자리만 1인 벡터 `[0, 0, 1]`(one-hot)에 마이너스를 붙인 것이다. 그래서 "이것이 one-hot"이라고 한 것.

**①과 ②를 합쳐 클래스 3개, 정답 3번으로 전부 써 보면.** loss = log(e^z₁ + e^z₂ + e^z₃) − z₃.

| 미분 변수 | ① log(S)에서 | ② −z₃에서 | 합 |
|---|---|---|---|
| z₁ | p₁ | 0 | p₁ − 0 |
| z₂ | p₂ | 0 | p₂ − 0 |
| z₃ (정답) | p₃ | −1 | p₃ − 1 |

표의 "합" 열이 `[p₁, p₂, p₃] − [0, 0, 1]` = softmax − one-hot 이다. 일반식으로 쓰면
```
d loss / dz_i = p_i − onehot_i      즉  정답 칸: p_t − 1  (음수),   나머지 칸: p_i  (양수)
```

**숫자로.** 점수 `[2, 0.5, −1]`, 정답 2번. softmax = `[0.7856, 0.1753, 0.0391]`, one-hot = `[0, 0, 1]`.
```
기울기 = [0.7856 − 0, 0.1753 − 0, 0.0391 − 1] = [0.7856, 0.1753, −0.9609]
```
스크립트 B의 `logits.grad`가 이 값이다. 갱신은 `z ← z − lr·기울기` 이므로 2번 점수는 올라가고(−0.96을 빼니까) 0번·1번은 내려간다.
기울기의 크기도 뜻이 있다. 정답 칸은 `p_t − 1`이라 **정답에 준 확률이 낮을수록 세게 올리고**, 오답 칸은 `p_i`라 **확률을 많이 준 오답일수록 세게 내린다**.
세 값을 더하면 0이다(확률 합 1 − one-hot 합 1). 점수는 서로 뺏고 뺏기는 관계라 전체 합은 안 바뀐다.

### 라벨 불균형과 가중치
필터 데이터는 라벨의 88%가 N이다. 가중치 없이 학습하면 모델은 "N이라고 하면 대체로 맞는다"는 쪽으로 기운다.
`weight = where(target == Y, y_weight, 1)` 로 Y 예시의 loss를 키우면, Y를 놓치는 것이 더 아프므로 P(Y)가 전체적으로 위로 밀린다.

**풀어서.** 실전 loss 함수는 세 줄이다(맨 아래 "실전 코드에서는").
```python
ce     = F.cross_entropy(logits, targets, reduction="none")   # 예시마다 −log P(정답). 벡터
weight = torch.where(targets == y_id, y_weight, 1.0)          # 예시마다 가중치. 벡터
loss   = (ce * weight).sum() / weight.sum()                   # 가중 평균. 숫자 하나
```
- 1줄: `reduction="none"`이라 평균을 내지 않고 예시 개수만큼의 −log P를 벡터로 돌려준다(기본값은 평균 하나).
- 2줄: `where(조건, a, b)`는 조건이 참인 칸은 a, 거짓인 칸은 b. 정답이 Y인 예시는 y_weight, N인 예시는 1.
- 3줄: 같은 자리끼리 곱해서 더하고, weight 합으로 나눈다. 이것이 **가중 평균**이다.

예시 4개(Y, N, N, Y), y_weight = 3, 모델이 낸 −log P가 `[0.5, 0.1, 0.2, 0.4]` 라면
```
ce     = [0.5, 0.1, 0.2, 0.4]
weight = [ 3 ,  1 ,  1 ,  3 ]
loss   = (0.5·3 + 0.1·1 + 0.2·1 + 0.4·3) / (3+1+1+3) = 3.0 / 8 = 0.375
```
보통 평균이면 `(0.5+0.1+0.2+0.4)/4 = 0.3` 인데, Y 예시 둘을 3번씩 센 셈이라 0.375로 올라간다. y_weight = 1이면 weight가 전부 1이라 `ce.sum()/4`, 즉 보통 평균과 같다.

왜 P(Y)가 올라가나. 예시 10개(Y 1개, N 9개)에 모델이 모든 예시에 똑같이 P(Y) = p 를 낸다고 하자. 그러면
```
loss = [ y_weight · (−log p)  +  9 · (−log(1 − p)) ] / (y_weight + 9)
         └ Y 예시: 정답 Y에 준 확률 p ┘   └ N 예시 9개: 정답 N에 준 확률 1−p ┘
```
이 loss를 가장 작게 하는 p는 `y_weight / (y_weight + 9)` 다(미분해서 0 놓으면 나온다).

| y_weight | loss 최소인 p = P(Y) |
|---|---|
| 1 | 1/10 = 0.10 |
| 3 | 3/12 = 0.25 |
| 9 | 9/18 = 0.50 |

가중치 없이는 모델이 "P(Y) = 0.1, 즉 거의 N"이라고 해도 loss가 최소다. 데이터의 88%가 N이면 "다 N"이 꽤 좋은 답이라 모델이 그쪽으로 기운다.
Y 예시에 가중치 9를 주면 Y 하나 놓치는 벌점이 N 아홉 개 놓치는 것과 같아져서, 최적 P(Y)가 0.5로 올라온다.
실제 모델은 예시마다 다른 p를 내지만 방향은 같다: 기울기 쪽에서 보면 Y 예시의 기울기(= "P(Y) 올려라")에 y_weight가 곱해져, **Y 예시가 당기는 힘만 y_weight배** 세진다. 그래서 겹치는 영역의 예시들까지 P(Y)가 위로 밀린다(스크립트 C, 아래 실험 표).

## 실험해 보기 - Y 가중치 (실제 돌린 결과)

| 가중치 | Y 예시의 평균 P(Y) | N 예시의 평균 P(Y) | 임계값 0.5에서 P / R / F1 | F1이 가장 좋은 임계값 |
|---|---|---|---|---|
| `--y-weight 1` | 0.55 | 0.05 | 0.75 / 0.57 / 0.65 | 0.3 (F1 0.69) |
| `--y-weight 3` | 0.70 | 0.10 | 0.61 / 0.75 / 0.67 | 0.7 (F1 0.68) |
| `--y-weight 9` | 0.81 | 0.19 | 0.44 / 0.88 / 0.58 | 0.7 (F1 0.68) |

**경향**
- 가중치 ↑ → P(Y) 전체가 위로 밀린다(Y 예시도, N 예시도). 같은 임계값에서 recall ↑, precision ↓.
- **임계값을 훑어서 고르면 최고 F1은 가중치와 거의 무관하다**(0.68~0.69). 가중치는 "P(Y)의 눈금"을 옮기는 것이고 임계값이 그 눈금을 다시 자르기 때문.
- 그러면 가중치는 언제 중요한가: **임계값을 못 고르는 상황** - 서비스는 모델이 greedy로 낸 `Y`/`N` 글자를 그대로 쓴다(= 임계값 0.5 고정). 이때 가중치 1이면 recall 0.57, 가중치 3이면 0.75.
- 너무 큰 가중치(9)는 임계값 0.5에서 precision이 0.44로 떨어진다. 필터는 precision이 떨어지면 답변에 엉뚱한 문서가 섞이므로 과하면 해롭다.

그래서 실전에서는 "첫 학습의 val Y 확률 분포를 보고 가중치를 정한다": 가중치 1로 학습한 모델의 P(Y) 분포를 보고, greedy(0.5)에서 Y를 너무 안 내면 가중치를 올리거나 임계값을 내린다.

## 실전 코드에서는
```python
ce = F.cross_entropy(logits, targets, reduction="none")   # 답 토큰마다 -log P(정답)   <- A
weight = torch.where(targets == y_id, y_weight, 1.0)       # ' Y' 토큰만 가중치         <- C
return (ce * weight).sum() / weight.sum()                  # 가중 평균
```
`targets`가 토큰 id(어휘 248,320개 중 하나)이고 클래스가 248,320개라는 것만 다르다. 주의: 답 토큰 52개 중 ' Y'/' N'은 10개뿐이고 나머지 42개는 `[`, `1`, `]`, `\n` 같은 형식 토큰이다 - 이것들은 금방 loss 0이 되고, 실제 학습은 Y/N 10개에서 일어난다(6단계에서 토큰별 loss로 확인).
